# 板块 A：体系架构设计方案（中期产出成果）

## A-1 研究背景与目标

- **要点**：
  - 新型电力系统：设备多、处理器架构多、OS 类型多、协议多、实时等级差异大、安全要求高。
  - 传统"单设备/单OS/单业务"模式无法支撑跨设备、跨层级、跨地域协同。
  - 目标：形成"云—边—端三域 + 协同服务层 + 四横向平面"的统一体系架构。
- **配图**：电力物联现状痛点图（左：异构孤岛；右：统一体系）。
- 讲稿备注：强调安全是五大设计目标之一（软硬件结合、全生命周期安全可信）。

## A-2 总体体系架构（一张总图）

- **要点**：
  - 三域：云端（全局治理/分析，不进本地实时闭环）、边缘（汇聚/低时延/断网自治）、终端（硬实时/确定性控制）。
  - 协同服务层：把异构 OS 能力统一抽象为 资源/设备/服务/任务/数据 五类对象。
  - 四平面：资源与任务、数据与通信、**安全可信**、可观测与评测。
- **配图**：★ 核心总架构图（三层横向 + 协同层居中 + 四平面竖向贯穿）。全场演讲反复回指这张图。
- 讲稿备注：点明"协同层像统一接口/USB 标准"，屏蔽芯片、内核、设备、协议差异。

## A-3 三域职责与协同计算模型

- **要点**：
  - 端：固定优先级抢占、优先级继承、Tickless 低功耗、失联本地自治。
  - 边：混合关键性——实时域与通用域资源预算与设备隔离。
  - 云：策略生成、跨区域编排、跨层级关联分析。
  - 任务生命周期闭环：生成→画像→可行域筛选→分层放置→监测→动态调整（综合实时截止期/数据位置/网络质量/可信等级）。
- **配图**：任务生命周期闭环图 + 三域职责分工表。
- 讲稿备注：强调"数据敏感任务只能部署在满足可信等级与数据驻留要求的节点"——引出安全平面。

## A-4 安全可信框架（承上启下页）

- **要点**：中期稿 12 章五个子领域——
  - 12.2 语言与组件安全 · 12.3 隔离与可信执行 · 12.4 可信启动 · 12.5 动态安全与恢复；
  - 威胁模型九类，重点：内存并发缺陷、跨组件越权、**虚拟化逃逸**、异构外设/AI 加速器可信 I/O。
- **配图**：安全四子领域 + 九类威胁映射图。
- 讲稿备注：这页是 A→B 的桥——"安全可信框架里最硬核、最能拉开技术深度的，就是研究内容3的内核态飞地增强机制，下面重点讲。"

# 板块 B：研究内容3 —— 安全能力增强机制

## B-1 研究内容3 目标与技术挑战

- **要点**：
  - 目标（原文）：基于强安全语言与内核态飞地结合的系统层安全增强机制；设计基于硬件隔离的高安全内核态飞地架构；提出内核组件隔离与程序切片保护方法；最大化增强电力专用物联 OS 内核安全保障。
  - 挑战：① 传统 TEE 绑定特定硬件厂商（Intel SGX/AMD SEV/ARM TrustZone），电力设备芯片异构，难统一；② 内核庞大，单一漏洞即危及全局；③ 全飞地保护开销大，需精准切片。
- **配图**：问题图——异构芯片 × 厂商专有 TEE = 无法统一。
- 讲稿备注：抛出核心命题——"如何在不绑定硬件厂商的前提下，为异构电力设备内核提供飞地级隔离？"

## B-2 技术根基：HyperEnclave（已验证的方法基础）★关键页

- **要点**：
  - 依据成果：**HyperEnclave（USENIX ATC 2022，贾越凯 等，第一作者）** + **Rust 页表形式化验证（ASPLOS 2024，同团队）**——均为系统领域顶会。
  - 核心创新：**不依赖厂商专有 TEE，用普遍可得的虚拟化扩展（VMX/SVM + 二级页表 EPT/NPT）构造飞地**；跨平台（已在商用 AMD 服务器实现并在头部金融科技公司真实部署）。
  - 监控器（RustMonitor）用 **Rust** 编写——强安全语言 + 飞地天然结合；ASPLOS'24 进一步对页表实现做**形式化验证**。
- **配图**：HyperEnclave 架构示意（不可信内核世界 | 极小 Rust 监控器/隔离根 | 受二级页表保护的飞地）。
- 讲稿备注：明确定位——"这是本课题飞地机制的已验证方法基础，思路已被顶会与真实部署证明可行；我们的工作是把它落到电力物联 OS。"

## B-3 内核态飞地架构（本课题设计）

- **要点**：
  - 三要素：① 隔离根 = 极小 Rust hypervisor（对应 axvisor）；② 硬件隔离 = 二级页表（EPT/NPT）把飞地内存从不可信内核视图中移除；③ 受控进出 = 飞地门（gate/trampoline），唯一合法通道。
  - 安全属性：不可信内核即使被攻破，也无法读写飞地内存；飞地内代码/数据机密性与完整性受硬件保护。
  - 面向电力物联的适配：跨 x86/ARM/RISC-V/LoongArch（借 axvisor 多架构能力）；轻量化以适配边/端资源约束。
- **配图**：内核态飞地架构图（世界切换 + 二级页表隔离 + 门）。
- 讲稿备注：强调"跨平台"正是电力异构芯片场景最需要的——不绑厂商。

## B-4 内核组件隔离方法（本课题设计）

- **要点**：
  - 把高安全内核组件（如密钥管理、可信 I/O 校验、认证）从庞大内核中剥离，放入飞地。
  - 隔离手段分层：语言层（Rust 类型/所有权）+ 地址空间层（二级页表 / 页保护属性 page_prop）+ 访问控制层（LSM 框架）。
  - 组件间只能经明确接口（受控内存访问器 GuestMemoryAccessor 式契约）交互，攻击面收敛为可枚举边界。
- **配图**：分层隔离图（语言层→地址空间层→访问控制层）。
- 讲稿备注：呼应中期稿 12.2"unsafe/C 集中封装为可审计最小边界"。

## B-5 程序切片保护方法（本课题设计）

- **要点**：
  - 问题：把整个组件全放进飞地，开销大、飞地体积大（攻击面反增）。
  - 方法：按数据流/控制流分析，切出**敏感切片**（触碰密钥、凭证、可信状态的代码与数据）与**普通切片**；只对敏感切片施加飞地保护。
  - 收益：保护开销最小化 + 飞地可信计算基（TCB）最小化 = 安全性与性能兼顾。
- **配图**：切片示意（组件 → 敏感切片进飞地 / 普通切片留常规世界）。
- 讲稿备注：这是"最大化增强内核安全保障"里"最大化"的技术含义——精准而非全量保护。
