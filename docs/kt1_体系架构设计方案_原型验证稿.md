> 配套：《课题1 云边端协同的电力专用物联操作系统体系架构设计方案（中期稿 V0.1）》

## 1 概述

本方案面向云端、边缘侧与终端侧异构计算环境，构建“云—边—端三域、一个协同服务层、四类横向保障能力”的电力专用物联操作系统体系架构。三域体现部署位置与职责差异，协同服务层提供跨域统一机制，**资源与任务、数据与通信、安全可信、可观测与评测**四个平面贯穿全栈。

安全方面，中期稿提出 **Rust 语言安全 + 组件隔离 + 虚拟化/TEE + 可信启动 + 远程证明 + 动态度量** 相结合的全栈设计。本稿的核心工作，是把其中**已在原型上落地的部分**用可复现证据固定下来，并明确尚未覆盖的部分作为后续承接方向。

原型选型与依据：课题端/边侧原型采用 **ArceOS（模块化 Rust unikernel/内核框架）+ Starry（Linux 兼容内核）+ axvisor（ArceOS 系虚拟化）** 技术栈，对应中期稿 3.4 节“Rust 安全操作系统”的技术基础。该栈已实证支持 **x86_64 / AArch64 / RISC-V / LoongArch 四种处理器架构**，契合电力物联“多处理器架构”的现实需求（axvisor 多架构 guest 引导：#930 x86_64、#768/#1207 LoongArch、#788/#883 RISC-V）。

## 2 总体体系架构

### 2.1 三域两层四平面

- **端侧（终端域）**：实时感知与确定性控制，采用固定优先级抢占、优先级继承、Tickless 低功耗，云边失联时保留本地安全策略与关键控制能力。
- **边缘侧（边缘域）**：设备汇聚、低时延处理、断网自治，混合关键性节点对实时域与通用域做资源预算与设备隔离。
- **云端（云域）**：全局资源治理、跨区域编排、数据分析；对硬实时控制仅提供策略与分析支持，不进入本地毫秒/微秒闭环。
- **协同服务层**：位于内核与业务之间，将异构 OS 能力统一表示为资源/设备/服务/任务/数据对象，提供跨层级生命周期管理。
- **四平面**：资源与任务、数据与通信、**安全可信**、可观测与评测。

### 2.2 原型对体系架构的支撑边界（如实说明）

| 体系要素 | 原型验证状态 |
|----------|--------------|
| 端/边侧内核、运行时、虚拟化 | ✅ 有 ArceOS/Starry/axvisor 原型与已合并实现 |
| 多架构（x86/ARM/RISC-V/LoongArch） | ✅ 四架构 guest 引导均已合并 |

| 协同层通信安全、远程证明 | ⬜ 后续承接（见 4.6） |

## 4 安全可信架构与原型验证（核心章节）

本章按中期稿 12.2–12.5 组织，每节给出**机制设计 → 原型实现 → 验证证据（已合并 PR/commit）**。所有 PR 均可在 rcore-os/tgoskits 查证，状态为 merged。

### 4.1 语言与组件安全（对应 12.2）

**机制设计**：安全敏感内核组件与运行时优先采用 Rust，利用所有权/借用/生命周期/类型系统消除释放后使用、双重释放、悬空指针、数据竞争；对必须使用 unsafe/C 的硬件访问集中封装为可审计的最小边界。

**原型实现**：
- 整个 ArceOS/Starry/axvm 栈以 Rust `#![no_std]` 编写，从语言层消除上述缺陷类别。
- **强类型地址**：`GuestPhysAddr` / `PhysAddr` 为不同类型，编译期阻止客户机物理地址与宿主物理地址混用。
- **unsafe 最小边界**：`axaddrspace` 的 `GuestMemoryAccessor` trait 将裸内存访问收敛为“返回 (宿主物理地址, 可访问字节数) 的受控接口”，把边界检查上升为类型契约。

**验证证据**：
| 证据 | 说明 |
|------|------|
| PR #920（merged 2026-05-25） | 修复跨 split file map 共享 page-cache 页逐出时的 use-after-free |
| PR #1120（merged 2026-06-06） | mmap `addr+length` 溢出直接拒绝，不再回绕（防整数溢出绕过检查） |
| PR #1534（merged 2026-07-08） | 拒绝越过 EOF 的私有 mmap 缺页 |
| PR #1164（merged 2026-06-10） | file-backed mmap 在 EOF 处设界，不为越界页分配 frame |
| PR #1499（merged 2026-07-06） | page-cache 预分配设上界，防 OOM |

**验证结论**：语言与组件安全在原型上**已达成**——机制为架构级（类型系统 + trait 边界），且有多项已合并的内存安全修复佐证其在实践中生效。

### 4.2 并发与执行安全（支撑 12.2 的“数据竞争”与健壮性）

**机制设计**：把锁正确性与栈安全变成架构可验证/可捕获的属性，避免并发缺陷与栈溢出演化为可利用的内存破坏。

**原型实现与验证**：
| 机制 | 原型实现 | 验证证据 |
|------|----------|----------|
| lockdep 感知锁 | `ax-kspin` 自旋读写锁内建锁序检测 | PR #1397（merged 2026-06-29）；#1375/#1103 借此消除锁序回归 |
| 原子上下文睡眠检测 | `axtask` 的 might_sleep 框架，已进 std CI | PR #1235、#1689 |
| 任务栈 guard page | 栈尾映射不可访问页，栈溢出转为可捕获缺页 | PR #811（merged 2026-05-24） |
| 越界 hart 受控 park | 超 `MAX_CPU_NUM` 的副核 park 而非 panic | PR #919（merged 2026-05-25） |

**验证结论**：并发/执行安全**已达成架构级支撑**，且 lockdep 已纳入常态化 CI。

### 4.3 隔离机制（对应 12.3 前半：进程/容器/VM）

**机制设计**：在进程、容器、虚拟机多层级提供隔离；为跨域共享内存/设备访问设置显式权限。

**原型实现与验证**：

（1）**进程/容器隔离（✅ 已覆盖）**
| 机制 | 验证证据 |
|------|----------|
| seccomp + capabilities | PR #1275（merged 2026-06-18） |
| PR_SET_NO_NEW_PRIVS（提权阻断） | PR #810（merged 2026-05-24，含 OpenSSH 测试） |
| dumpable / no_new_privs 字段 | PR #797（merged 2026-05-25） |
| namespace / cgroup | PR #1031、#1642 |
| ABI 严格对齐（sigsetsize、uc_mcontext 偏移） | PR #900、#916 |

（2）**虚拟机隔离（🟡 框架具备，有已定位缺口）**
- 隔离基础：axvm 提供 guest 二级页表（NPT / stage-2）地址空间隔离；vCPU 后端已重构为 **OS-neutral**（与宿主 OS 解耦，攻击面收敛到明确 trait 边界）——PR #1550/#1523/#1553/#1556/#1467（2026-07 系列）。
- 跨域共享内存：`GuestMemoryAccessor` 提供显式权限边界（可访问字节数、只读标志）。
- **已定位缺口（对应威胁“虚拟化逃逸”）**：
  - issue #1730（高危）：GICR_INVLPIR 中断号越界，客户机可写宿主物理内存；
  - issue #1734（高危）：GITS_CBASER 客户机物理地址被当宿主地址解引用（缺 stage-2 翻译）；
  - issue #1745（中危）：未实现 MMIO 偏移触发 hypervisor panic（`todo!`）。

**验证结论**：进程/容器隔离**已覆盖**；虚拟机隔离**已具备架构框架但存在 3 项已定位的逃逸缺口**，是下一阶段第一优先。强类型地址（4.1）正是 #1734 的根治方向，OS-neutral 边界（本节）为收敛攻击面提供了结构基础。

### 4.4 可信执行与远程证明（对应 12.3 后半）

**机制设计**：分区/TEE 隔离、按可信等级动态划分隔离域、跨域完整性校验、向云/边远程证明启动链与运行状态。

**原型现状**：⬜ **尚未覆盖**。当前原型无 TEE（TrustZone/SGX/RISC-V PMP）集成、无度量根、无远程证明链路、无动态隔离域划分。

**后续承接路径**：引入 RISC-V PMP 或 ARM TrustZone 作为硬件隔离根；在 axvm 二级页表基础上扩展按可信等级的隔离域；共享内存访问器增加完整性度量（MAC/hash）；实现基于度量的 attestation 报告生成与验证。

### 4.5 可信启动（对应 12.4）

**机制设计**：对固件/引导/内核/运行时/关键应用逐级验签；更新包签名、版本依赖、灰度、回滚、证书撤销、紧急修复。

**原型现状**：⬜ **尚未覆盖**，且原型中存在若干**反向缺口**，恰可作为课题可信启动/更新安全的现实驱动：
- issue #1749（中危）：串口选择的 HTTP 内核缺少真实性校验；
- issue #1763（高危）：Fork PR 可在持久化自托管 Runner 上执行代码（供应链）；
- issue #1756/#1758/#1759：执行未固定的上游分支 / 以 root 安装未认证 APK。

**后续承接路径**：建立度量启动链（RoT → bootloader → 内核 → 运行时）；更新包强制签名与版本/依赖记录；对 CI/供应链引入固定引用与最小权限。

### 4.6 动态安全与恢复（对应 12.5）

**机制设计**：运行期持续采集完整性/访问/通信/资源异常；可信度下降时减少可访问服务、迁移敏感任务、隔离异常设备或切换恢复镜像。

**原型实现与验证**：
| 能力 | 原型实现 | 验证证据 | 状态 |
|------|----------|----------|------|
| 崩溃可观测 | panic backtrace hook | PR #1653（merged 2026-07-30） | 🟡 |
| 分配回溯 | memtrack | PR #1020 | 🟡 |
| 运行期锁检测 | lockdep | PR #1397 | 🟡 |
| 受控降级 | guest 缺页受控恢复、越界 hart park | PR #788/#883/#919 | 🟡 |

**验证结论**：具备**异常采集与受控降级**的部分能力，但缺少课题要求的“可信度评估 → 服务降级/任务迁移/设备隔离”闭环响应引擎，需在后续实现运行期完整性度量与可信度模型。

### 4.7 可信 I/O（对应 12.1“异构外设/AI 加速器”，电力物联特色）

**机制设计**：对异构外设与 AI 加速器的 DMA/内核指针访问强制边界与配额，防止设备侧越界破坏宿主。

**原型现状**：🟡 **有现实缺口，是课题最具场景针对性的着力点**：
- issue #1732（高危）：rknpu Submit 信任用户提供的内核指针与 DMA 地址；
- issue #1739（高危）：mpp-service JPEG 偏移可让 DMA 越过导入缓冲区；
- issue #1762（中危）：rknpu MemCreate 缺少 DMA 分配配额。

**后续承接路径**：为 NPU/VPU 提交路径引入 IOMMU/地址翻译校验、DMA 缓冲区边界与配额、用户指针经受控内存访问器解析——可直接复用 4.1 的 `GuestMemoryAccessor` 模式。

### 5.2 验证方法学说明

- **验证口径**：所有“✅/🟡”项均以 tgoskits 已合并（merged）PR/commit 为实现佐证，代码已落地并通过仓库 CI，故为原型级已实现证据，而非设计陈述。
- **缺口口径**：所有“⬜”项及 🟡 项中的“已定位缺口”，均引用 tgoskits 已登记的安全 issue（含审查基线 commit `9daea706` 与 CWE 分类），是课题原型已发现、下一阶段可承接的 backlog，而非未知风险。
- **归属口径**：按课题约定，凡 tgoskits 已合并提交均计入课题原型成果，不再区分具体贡献者。

### 5.3 中期结论

1. **已达成并可作为中期成果汇报**：语言与组件安全、并发/执行安全、进程/容器隔离、内存安全——均有架构级机制与已合并、已过 CI 的多项实证，与课题“Rust 语言安全 + 组件隔离”主张高度吻合。
2. **有框架、待完善（下一阶段第一优先）**：虚拟机隔离已具备二级页表与 OS-neutral vCPU 框架，但存在 #1730/#1734/#1745 三项虚拟化逃逸缺口，直接对应威胁模型“虚拟化逃逸”。
3. **中后期需从架构新增**：TEE/分区隔离、可信启动链、远程证明、动态度量与可信度驱动的安全响应——原型基本空白，已给出明确承接路径。
4. **最具电力物联特色的着力点**：异构外设/AI 加速器可信 I/O（NPU/VPU 驱动 #1732/#1739/#1762），建议重点立项，且可复用现有受控内存访问器模式。
