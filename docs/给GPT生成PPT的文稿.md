## B-1 研究内容3 目标与技术挑战

## B-2 什么是内核态飞地（enclave）★概念页
- 定义：内核态飞地是一块基于**硬件隔离**的高安全执行区域。即使内核其余部分被攻破，攻击者也无法读写飞地内的代码与数据（机密性与完整性受硬件保护）。
- 与传统 TEE 的区别：不依赖厂商专有 TEE 指令（Intel SGX / AMD SEV / ARM TrustZone），而用**普遍可得的虚拟化扩展**（VMX/SVM + 二级页表 EPT/NPT）构造飞地——因而具备跨平台、跨厂商的适配能力。
- 构造原理三要素：
  - 隔离根：一个极小的、用强安全语言 Rust 编写的监控器（hypervisor）
  - 硬件隔离：二级页表（EPT/NPT）把飞地内存从不可信内核的地址视图中移除
  - 受控进出：飞地门（gate/trampoline）是进出飞地的唯一合法通道
- 可信度增强：飞地的页表实现可进一步施加形式化验证。
- 配图说明：画 enclave 原理三块——左"不可信内核世界"、中"极小 Rust 监控器（隔离根）"、右"受二级页表保护的飞地"，中间用"飞地门"连接。
- 讲稿备注：本页只回答"飞地是什么、靠什么隔离"，不涉及任何具体成果或归属。强调"不绑厂商、跨平台"正是电力异构芯片场景的关键价值。

## B-3 内核态飞地架构（本课题设计）
- 三要素：
  - 隔离根 = 极小 Rust hypervisor（对应 axvisor）
  - 硬件隔离 = 二级页表（EPT/NPT）把飞地内存移出不可信内核视图
  - 受控进出 = 飞地门（gate/trampoline），唯一合法通道
- 安全属性：不可信内核即使被攻破，也无法读写飞地内存；飞地内代码/数据机密性与完整性受硬件保护
- 面向电力物联适配：跨 x86/ARM/RISC-V/LoongArch（借 axvisor 多架构能力）；轻量化适配边/端资源约束
- 讲稿备注：强调"跨平台"正是电力异构芯片场景最需要的——不绑厂商。

## B-4 内核组件隔离方法（本课题设计）
- 把高安全内核组件（密钥管理 / 可信 I/O 校验 / 认证）从庞大内核剥离，放入飞地
- 隔离手段分三层：
  - 语言层：Rust 类型/所有权
  - 地址空间层：二级页表 / 页保护属性（page_prop）
  - 访问控制层：LSM（Linux Security Module）框架
- 组件间仅经明确接口（受控内存访问器契约，返回"宿主物理地址 + 可访问字节数"）交互，攻击面收敛为可枚举边界
- 配图说明：三层隔离堆叠图（语言层 / 地址空间层 / 访问控制层）。
- 讲稿备注：呼应"unsafe/C 集中封装为可审计最小边界"。

## B-5 程序切片保护方法（本课题设计）
- 问题：整个组件全放进飞地 → 开销大、飞地体积大（攻击面反增）
- 方法：按数据流/控制流分析，切分——
  - 敏感切片：触碰密钥/凭证/可信状态的代码与数据 → 进飞地保护
  - 普通切片：留常规世界
- 收益：保护开销最小化 + 可信计算基（TCB）最小化 = 安全性与性能兼顾
- 配图说明：一个组件分裂成两块——敏感切片（带锁图标，进飞地）/ 普通切片（留外）。
- 讲稿备注："最大化增强内核安全保障"里"最大化"的技术含义——精准而非全量保护。
